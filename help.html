AIDA browser star calibration workflow

Copyright © Juha Vierinen, Björn Gustavsson, and Codex.

This page is a compact checklist for using the browser calibrator to identify stars, fit the AIDA optical parameters, and export the result.

The automatic workflow is intended for wide-field cameras, roughly above 30 degrees field of view, looking at catalog stars brighter than magnitude 7. Some effort has been made to keep the fitting robust in real scenes with aurora, buildings, bad star detections, and nonlinear lens effects, but the solver still needs enough visible star structure to anchor the calibration.

Basic workflow

  1. Load an all-sky PNG, JPEG, or iPhone HEIC image. The bundled example image is loaded automatically when the page opens.
  2. Check the UTC timestamp, latitude, longitude, and altitude. The browser first tries EXIF metadata from the image. If that is not available, known allsky7 filenames are used to fill time and station position.
  3. Check the initial camera parameters. The browser sets f1 = 1 and guesses f2 from the loaded image aspect ratio, so ordinary 16:9 images and 4:3 phone images start with different vertical focal scales.
  4. Use brightness, contrast, and the high-pass filter so stars are easy to see. The high-pass filter is on by default.
  5. The page opens in star pairing view, with the image in the background and catalogue stars circled in red. Press C to switch between pairing view and Stellarium-style catalog view. Press X to alternate pure image and pure Stellarium views with labels and pairing annotations hidden. The az/el grid remains visible in those views when enabled. Press N to toggle star names. The play/stop button next to Help starts or stops a generated background score with random harmonic phrases and subtle space-audio feedback while you work.
  6. Roughly align the catalog field of view before picking stars: left-drag the image to move the 90 degree elevation point, right-drag to rotate the azimuth grid, and use the mouse wheel to scale the horizontal and vertical focal lengths together.
  7. For a hands-off attempt, press L or the I'm feeling lucky... button. This follows the same bootstrap idea used in the graphical test cases: first a conservative magnitude-4 bright-star search, then a blind spherical asterism match to seed the selected optical model's rotation and coarse focal scale. It then fits the selected model in sweeps using the brightest matched stars first, expands to fainter stars with the improved projection, prunes obvious automatic outliers from the residual pattern, and repeats until the model stops improving. Late expansion stages only keep additional stars when they do not substantially increase the fit RMSE, because a bad automatic star usually worsens the residuals immediately.
  8. Hold S and click an image star. The local star position is refined with an interpolated Gaussian-smoothed density estimate. Release S, then click the matching red catalog star.
  9. Repeat until at least four reliable star pairs are available. More well-spread pairs usually gives a more stable lens fit.
  10. Press F for the robust randomized Nelder-Mead fit, or G for the ordinary least-squares Levenberg-Marquardt fit. Press Cmd/Ctrl Z to undo an accepted fit.
  11. Press R to inspect fit residuals. The suggested red marker identifies the star pair furthest from the median residual pattern.
  12. Use the export buttons to copy either the fitted optpar = [...] array or mapper code. When running from the local server, use Submit as test case to store the calibrated image, picked star locations, residuals, timestamp, coordinates, and best-fit lens model under test_cases/.

Useful controls

  • S: enter star picking and select an image star while held.
  • C: toggle star pairing view and Stellarium-style catalog view.
  • X: alternate pure image view and pure Stellarium view, hiding labels and pairings while respecting the az/el grid toggle.
  • N: show or hide catalog star names in the current view.
  • Play/stop button next to Help: start or stop the evolving generated planetarium score and subtle interaction blips.
  • K: show or hide tiny KDE subpixel dots at the picked image-star positions.
  • T: show or hide the lucky asterism line overlay.
  • A: show or hide the az/el grid.
  • L: run I'm feeling lucky..., which automatically detects, identifies, seeds, and iteratively fits the selected model. Running it again respects marked bad star finder positions.
  • F: fit the selected model parameters with robust Nelder-Mead.
  • G: fit the selected model parameters with Levenberg-Marquardt.
  • Cmd/Ctrl Z: undo the most recent accepted fit or automatic pairing batch.
  • D + click: delete the nearest matched star pairing.
  • M + click or drag: paint a 100 px radius circle over bad yellow star finder detections. Their raw pixel positions are saved in test-case metadata and ignored by later automatic searches.
  • R: show or hide residual view.
  • Submit as test case button: save the current image metadata, [optmod, ...optpar], residuals, manual or automatic pairings, and bad star finder detection positions into aida_js_calibrator/test_cases/ when using the local server.
  • Esc: cancel the current star selection or close the density popup.
  • Left mouse drag: move the field of view by shifting the 90 degree elevation point.
  • Right mouse drag: rotate the field of view around the 90 degree elevation point.
  • Mouse wheel: zoom the field of view by changing f1 and f2 together.

Field of view adjustment

The first alignment step is meant to be visual and approximate. Drag with the left mouse button until the catalog zenith is near the image zenith. Drag with the right mouse button to rotate the star field so bright catalog stars line up with the image orientation. Use the mouse wheel if the projected catalog field is too wide or too narrow. After the field is close, use S to create accurate star pairs and let the lens optimizer refine the selected model parameters.

Star picking details

When S is held, a magnified view follows the mouse. Click near the image star; the magnifier disappears and a density-estimate popup is placed away from the click area. The selected star position is found from a 40x interpolated local image patch smoothed with a Gaussian kernel, and the popup shows the unfiltered interpolated bitmap underneath scientific contour lines of the smoothed density estimate.

Press K to inspect only the picked subpixel image-star positions. In this KDE-dot mode all other overlays are hidden, which is useful for checking whether the centroiding is landing on the intended stars.

Residuals and undo

Residual mode draws the fitted catalog location and the selected image location for each pair. The suggested removal marker is based on the star whose residual is furthest from the main residual pattern, rather than simply the largest absolute residual.

Accepted fits and automatic pairing batches are stored in an undo stack. Use the Undo button or Cmd/Ctrl Z to restore the state from before the latest accepted fit or automatic pairing run. Loading a new image or removing all star pairings clears the undo history.

Lens models

The model selector includes the self-contained parametric AIDA models from the MATLAB code: optmods 1, 2, 3, 4, 5, and 12. The lookup-table and instrument-specific MATLAB variants are not included because they require external calibration tables or camera-specific code. Brown-Conrady is provided as a standard radial/tangential distortion alternative under browser optmod 20; see Nowakowski and Skarbek (2013), "Analysis of Brown camera distortion model", SPIE volume 8903.

AIDA radial models (optmod 1,2,3,4,5,12) \[ \begin{aligned} \mathbf{o}_{\mathrm{AIDA}}&=[f_1,f_2,\alpha,\beta,\gamma,d_u,d_v,a_r]\\ \theta&=\tan^{-1}\!\left(\frac{\sqrt{s_1^2+s_2^2}}{s_3}\right)\\ q_1(\theta)&=\tan\theta\\ q_2(\theta)&=\sin(a_r\theta)\\ q_3(\theta)&=a_r\theta+(1-a_r)\tan\theta\\ q_4(\theta)&=\theta^{a_r}\\ q_5(\theta)&=\tan(a_r\theta)\\ q_{12}(\theta)&= \begin{cases} \tan(a_r\theta)/a_r,&a_r>0\\ \theta,&a_r=0\\ \sin(a_r\theta)/a_r,&a_r<0 \end{cases}\\ x&=W\left(f_1\frac{s_1}{\sqrt{s_1^2+s_2^2}}q(\theta)+\frac{1}{2}+d_u\right)-1\\ y&=H\left(f_2\frac{s_2}{\sqrt{s_1^2+s_2^2}}q(\theta)+\frac{1}{2}+d_v\right)-1 \end{aligned} \]
Brown-Conrady radial/tangential model \[ \begin{aligned} \mathbf{o}_{\mathrm{BC}}&=[f_1,f_2,\alpha,\beta,\gamma,d_u,d_v,k_1,k_2,k_3,p_1,p_2]\\ x_n&=s_1/s_3,\quad y_n=s_2/s_3,\quad r^2=x_n^2+y_n^2\\ L(r)&=1+k_1r^2+k_2r^4+k_3r^6\\ x_d&=x_nL(r)+2p_1x_ny_n+p_2(r^2+2x_n^2)\\ y_d&=y_nL(r)+p_1(r^2+2y_n^2)+2p_2x_ny_n\\ x&=W\left(f_1x_d+\frac{1}{2}+d_u\right)-1\\ y&=H\left(f_2y_d+\frac{1}{2}+d_v\right)-1 \end{aligned} \]
\(f_1, f_2\) horizontal and vertical focal scale factors.
\(\alpha,\beta,\gamma\) camera rotation angles in degrees.
\(d_u, d_v\) principal-point offsets in normalized image coordinates.
\(s_1,s_2,s_3\) star direction vector after camera rotation.
\(W,H\) image width and height in pixels.
\(x,y\) 0-based image pixel coordinates.
\(\theta\) off-axis angle from the camera boresight.
\(q(\theta)\) radial projection law for the selected AIDA model.
\(a_r\) AIDA radial model parameter.
\(x_n,y_n\) normalized pinhole image coordinates.
\(r\) radius in normalized pinhole coordinates.
\(k_1,k_2,k_3\) Brown-Conrady radial distortion coefficients.
\(p_1,p_2\) Brown-Conrady tangential distortion coefficients.
\(x_d,y_d\) distorted normalized image coordinates.

The rotation angles are calibration parameters for the camera attitude. In practical use, \(\alpha\) and \(\beta\) tilt the optical axis so the projected zenith point moves across the image, while \(\gamma\) rolls the star field around that optical axis. The implementation applies the same rotation convention in the browser, the copied Python export, and the AIDA reference camera model.

For ordinary rectilinear lenses and narrow or moderate fields of view, start with optmod 1 or Brown-Conrady. Brown-Conrady is usually the more useful choice for phone cameras and other lenses with radial and tangential distortion; it has worked well with iPhone images. For fisheye and all-sky cameras, optmod 2, 3, 4, 5, or 12 are better starting points because their radial laws are written directly in off-axis angle. Optmod 2 is a sine-like fisheye model, optmod 3 is a flexible blend of equidistant and rectilinear behavior, optmod 4 is a power-law equidistant variant, optmod 5 is a scaled rectilinear model that can become steep at large fields of view, and optmod 12 smoothly switches between sine-like, equidistant, and tangent-like radial laws depending on the sign of \(a_r\).

Test cases

Saved test cases live under aida_js_calibrator/test_cases/. Each case directory contains the calibrated image and a metadata.json file with image name, UTC timestamp, site coordinates, manually or automatically paired stars, residuals, and an [optmod, ...optpar] array whose first element is always the optical model number. To add a new case from the browser, run npm run serve, calibrate an image, and press Submit as test case.

Export notes

The copied optpar array always starts with the optical model number. For AIDA radial models it contains [optmod, f1, f2, alpha, beta, gamma, du, dv, radial_alpha]. For the Brown-Conrady model (browser optmod 20), it contains [20, f1, f2, alpha, beta, gamma, du, dv, k1, k2, k3, p1, p2]. The export language selector can copy the array and mapper code as Python, Julia, C, or MATLAB. The generated mapper code reads the model number from the first element before applying the parameter vector. The Python mapper includes the existing numerical image_to_az_el inverse; the Julia, C, and MATLAB exports provide the same forward az_el_to_image projection so they can be embedded in analysis code and inverted numerically when needed.

The inverse mapping is most meaningful for pixels inside the calibrated field of view and above the horizon. If the lens model is poorly constrained, add or remove star pairs and refit before exporting.
